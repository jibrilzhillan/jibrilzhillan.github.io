Loom Machine Monitoring System

An ESP32 node that clips onto a weaving loom, detects every stop and its cause, and reports it over MQTT to a production dashboard, replacing handwritten operator logs.

My role
Hardware & firmware engineer, dashboard designer
Team
2 people
Period
Jul–Dec 2024, resumed Oct 2026
Status
Working prototype, PCB in progress

The problem

Management wanted real insight into how effectively the weaving floor runs. Loom stops were recorded by hand in operator notes, so analysis was slow or did not happen at all.

The goal was a system that tracks each loom's downtime and output around the clock, without modifying the machines, so the company can make data-driven decisions. The first milestone: a working proof of concept, fast.

Architecture

Node and server overview. Each loom gets its own node; all nodes report to one broker over the factory Wi-Fi.

What I built

  • Automatic stop detection. Each node tells when a loom stops and restarts, and why it stopped, by combining several signals from the machine. Downtime is timestamped at the moment it happens, with no operator input.
  • Non-invasive sensing. All sensors clip on or tap existing signals. Nothing on the loom's control circuit is modified.
  • No lost data when the network drops. Events are sent in real time over MQTT and buffered on the node until the server confirms them, so a power cut or network outage does not lose production data.
  • Built for the factory floor. Nodes are set up from a phone, and a display and status lights show machine, network and sensor health at a glance.
  • Maintainable firmware. Rebuilt the original Arduino prototype in ESP-IDF for finer control and more efficient code, with the core logic unit-tested.
  • Custom PCB. Designed the node board in KiCad, now in final review before fabrication.
  • Dashboard design. Designed the production dashboard and its data model with my teammate, aligned with the company's manufacturing execution system.
Hardest part: the client had no fixed requirements and the team came from different backgrounds. I kept the project moving with frequent check-ins and by documenting every decision, test and open question, so requirements could take shape as the prototype grew.

Result

  • Working prototype; downtime tracking functional end to end
  • Bench-tested: no events or counts lost through a 10-minute broker outage
  • Prototype tested on 1 of the factory's 18 looms
  • PCB fabrication and enclosure in progress
  • Dashboard: downtime view done; output view and factory deployment pending
