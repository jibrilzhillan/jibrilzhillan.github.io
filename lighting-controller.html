Audio-Reactive Lighting Controller

A .NET command-line app that turns a song and a simple cue file into a synchronized light show, driving LED strips and a lamp through an ESP32 lighting controller over Wi-Fi.

My role
Research, software design & implementation
Team

Period
Jan–Feb 2026
Stack

Completed

The problem

A commercial photo box needed lighting that moves with the music: calm ambient effects between sessions, and a choreographed, beat-reactive show while a song plays. The show had to be easy to change per song and run reliably on a Windows PC operated by non-engineers.

I researched how lighting can be synchronized to audio and which hardware it needs, then turned the client's needs into a technical specification. My teammate built the ESP32 lighting controller; I designed and built the software that runs the show.

Architecture

LedCLI plays the song and switches scenes on cue; the effects engine reacts to the audio and streams frames to the controller.

What I built

  • Shows defined as data, not code. Each song has a JSON cue timeline: at each timestamp, which effect runs on which light segment (LED perimeter, lamp) and whether to fade or cut. New shows can be written without touching the program.
  • Music-synchronized cue scheduling. The app plays the song with NAudio and publishes the playback position every 200 ms as a reactive stream. A scheduler fires each scene change when its cue time is reached, and handles pause, resume and stop from the keyboard.
  • Audio-reactive effects engine integration. The app runs a real-time audio analysis and effects engine in the background and controls it through a REST API: it starts the engine, loads the configuration, prepares the scenes and switches between them during the show.
  • Self-checking startup. One init command checks that the lighting controller answers on the network, that the configured audio device exists, and that the effects engine starts and accepts its config. Each failure returns its own error code and is written to a log file.
  • Ambient mode and smooth transitions. An ambience command runs idle effects between sessions, with fading transitions so lights never jump.
  • Documentation for operators. Wrote tutorials and troubleshooting guides so the client's staff can run the system and recover from faults on their own.
Key decision: focus the effort on what the client actually needed: reliable startup, per-song choreography and easy operation.

Result

  • Project completed: software and hardware working together end to end
  • One command initializes the system, one plays a fully choreographed song
  • Song shows authored as JSON cue files, separate from the code
  • User tutorials and troubleshooting guide delivered
